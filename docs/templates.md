元の文面: Claude Docs「FDM・AIセキュリティ診断 契約書ひな形（下書き）」→ `templates/source/contracts.md`（**原文。書き換えない**）。

## 使い方
```bash
scripts/build-templates          # 原文 → 8つに分割（templates/parts/）→ PDF と入力欄の座標（templates/out/）。何度でも作り直せる
scripts/check-templates          # 分割・［…］の分類・原文と PDF の本文の突き合わせ・欄の位置・設定の反映
scripts/check                    # 上に加えて、ops/ のテストやシェルの構文など、運用部品をまとめて検査（CI でも走る）
op run --env-file=.env.mooore.tools.tpl -- scripts/upload-templates --dry-run   # 登録の中身だけ確認（通信しない）
```
必要な道具: Python 3、Google Chrome（`CHROME_BIN` で指定も可）、Noto Sans/Serif CJK JP（フォント）。`scripts/build-templates` が `templates/.venv` を自動で作る。

## ［　］の2種類
- **A. 一度決めれば全案件で同じもの → `templates/config.json`。** PDF を作るときに埋め込む。値を変えて `scripts/build-templates` をやり直せば、全書面に反映される（`scripts/check-templates` が、値を変えると PDF に反映されることを毎回確かめる）。**`moore_address` と `moore_representative` は、まだ「［小林が記入］」のまま。** 記入して作り直し、`scripts/build-templates --strict` が通れば、未記入は無い。
- **B. 案件ごとに入れるもの → Documenso の入力欄。** 名前は、文面の［　］の言葉と同じ日本語（例: 「対象業務」）。誰が入れるかは `templates/fields.json` の `customer`（お客様）／`moore`（ムーア）。
  - お客様: 会社名、住所、代表者 役職・氏名、同意者・許可者 役職・氏名、甲の連絡窓口、締結日・許可日・同意日
  - ムーア（送る前に入力）: 契約の種類、プラン、規模、対象業務、測る数字、確認条件、承認者・方法、承認なしで実行してよい範囲、期間、料金、支払い、定着支援の有無、サポートの選択、診断の対象・対象外・期間・時間帯・方法・アカウント、乙の環境を通るデータ・保存期間・権限、立替の上限、別紙の表、AI顧問の月の上限・お試しの上限・開発の月額枠・成果報酬の条件
  - どちらの書面にも、署名欄: お客様の署名と日付、ムーアの署名と日付
- **原文との対応は機械で守る。** `fields.json` は、すべての［…］を1つずつ分類する規則表。**分類されていない［…］、どの書面でも使われない規則、原文にない行があると、ビルドが止まる。** 原文を直したら、`fields.json` の規則も合わせて直す。

## Documenso への登録
### API で（おすすめ）
1. ★ Documenso → Settings → API Tokens でトークンを作り、1Password の `mooore-sign` に `DOCUMENSO_API_TOKEN` として入れる。
2. `scripts/build-templates` → `scripts/check-templates`。
3. `op run --env-file=.env.mooore.tools.tpl -- scripts/upload-templates`（8つ）。作り直すときは `--replace`（同名のテンプレートを削除してから作る）。1つだけなら `--only 03a_trial`。
- 登録の中身: 種類 = TEMPLATE、受信者 = お客様（署名者・1番目、宛先は仮の `customer@example.com`）→ ムーア（署名者・2番目、`hkobayashi@mooores.com`）、署名順 = 順番に（SEQUENTIAL）、言語 = 日本語、**アクセス認証 = 二要素認証（`TWO_FACTOR_AUTH`）**、入力欄 = `templates/out/*.fields.json` の座標。
- **確認済み（2026-11-10）:** 8つとも、初回の実行でエラーなく登録できた。画面で、一覧に8つ（名前の頭に【下書き】、非公開）、NDA と個別契約書（お試し）の中身（ソース PDF、署名順序が有効、グループ1 = お客様、グループ2 = ムーア、言語 = 日本語、**ドキュメントへのアクセス = 2要素認証を必須にする**、入力欄の数と名前と位置が PDF の空欄の上）を確認した。残りの6つの中身は、同じ手順で作ったが、画面では確認していない。
- トークンは `template-upload`（3か月）。1Password の `mooore-sign/DOCUMENSO_API_TOKEN`。

### 画面で（API が使えないとき）
Templates → Create template → PDF（`templates/out/<名前>.pdf`）をアップロード → 受信者を2人（お客様を1番、ムーアを2番、順番に署名）→ 入力欄を `templates/out/<名前>.fields.json` の一覧（ページ・位置・大きさ・種類・入力する人）のとおりに置く → 設定で「アクセス認証」を二要素認証にする。

## 二要素認証
- Documenso の「アクセス認証 = 2FA」は、**メールに届く確認コード**（アカウント不要）。署名者は、コードを入れて初めて書類を開ける。ドキュメント全体の設定なので、**ムーア側の署名者にも掛かる**。
- API で登録したテンプレートは、`globalAccessAuth: ["TWO_FACTOR_AUTH"]` が入っている（NDA の設定画面で、「2要素認証を必須にする」が入っていることを確認した）。**テスト送信で、確認コードのメールが届き、コードなしでは書類が開けないことを確かめる**（未確認）。

## 送り方
| 場面 | 送る組み合わせ |
|---|---|
| 初回（お試し） | NDA → 基本契約 → 個別契約（お試し） |
| お試しから本契約 | 個別契約（本契約） |
| セキュリティ診断 | NDA → 基本契約 → 個別契約（セキュリティ診断・強化）→ 診断作業の許可書 |
| AI顧問 | NDA → 基本契約 → 個別契約（AI顧問） |
| ムーア環境で運用 | 上記に加えて ムーア環境での運用の同意書 |

- **ムーアの入力欄は、送る前に入力する。** テンプレートから書類を作る API（`prefillFields`）か、画面の送信前の入力で、ムーア担当の欄（契約の種類・金額・期間など）を埋めてから送る。**どちらが画面で使えるかは未確認。**
- **3つを1回で送れるか:** Documenso の1つの書類には複数の PDF を入れられるため、`scripts/upload-templates --bundle trial` で「NDA＋基本契約＋個別契約（お試し）」を1つのテンプレート（3つの PDF）として登録できる設計にした。**登録・送信とも、まだ試していない（未確認）。** できなければ、上の表の順に、1つずつ送る。

## 弁護士確認後の差し替え手順（本番化）
1. 文面を直す: Claude Docs の文書を直し、Markdown で書き出して `templates/source/contracts.md` に置き換える（原文として）。
2. `fields.json` の規則を、直した文面に合わせる（`scripts/check-templates` が、合わない所を教える）。
3. `templates/config.json` の `draft_mark` を `false` にして、PDF の「下書き」表示を消す。`scripts/build-templates --strict` を通す。
4. `scripts/upload-templates --replace` で登録し直す。**テンプレート名の【下書き】は、`templates/build.py` の `DOCS` の名前を直して外す**（`--replace` は、新しい名前では古いものを消さないので、古い【下書き】は画面で消す）。送信済みの書類には影響しない。
5. 自分あてに送って、署名まで通す（確認項目は PR の説明を参照）。
